## 阶段 1：可选标题+标签

开源仓库不携带标题/标签生成 skill。宿主应用可以接入自己的标题生成器，也可以让用户手写 `标题.md`。

**操作**：
1. 若已有 `标题.md`，将其中的推荐标题、封面标题、发布简介和标签展示给用户确认。
2. 若没有 `标题.md`，允许直接启动 `scripts/main.ts`；脚本会从 `视频.md` 自动提取封面兜底标题。
3. 若宿主应用生成或更新了 `标题.md`，用户未明确确认前，停止执行，不得启动音频、字幕、配图或渲染阶段。

**`标题.md` 格式**：
```markdown
# 标题与发布信息

> 基于脚本：视频.md ｜ 生成时间：YYYY-MM-DD

## 视频号
### 候选标题
1. …
### 推荐
➤ 第 X 个：「…」——（理由）
### 封面标题
- line1：「…」
- line2：「…」
### 发布简介
…（必须控制在 380 字以内）
### 标签
#标签1 #标签2 …

## 抖音
…（同上格式）

## 小红书
…

## 公众号
…
```

**断点**：`标题.md` 存在且本轮用户已确认 → SKIPPED。若 `标题.md` 新生成、被更新，或无法确认是当前任务已审核版本，必须展示给用户确认。若 `标题.md` 不存在，则跳过本关卡并使用 `视频.md` 兜底。

使用 storyboard-ai 两阶段视觉方法：Director 生成 `global_plan`、连续段落边界和视觉字段，程序从 `视频.md` 按索引逐字组装 narration；随后 `image_prompt_tool` 根据每场视觉字段二次生成图片提示词。任何旧计划不能逐字还原当前文稿时自动废弃重建。

场景边界以视觉认知锚点为主，不按段落平均分配。先使用全片真实字幕时间轴，再规划主画布：每块画布必须对应一段完整、连续的语音，不预设固定时长，也不能为了卡某个秒数范围而截断内容；只有当核心判断、解释结构、对比关系、流程阶段或视觉认知锚点发生切换时才切场。每场内部规划 2–5 个 Beat，绑定连续字幕范围和真实毫秒时间；每场只选一种表达类型，最终画面控制 3–5 个主要对象和至少 35% 留白。

## 场景生命周期

全片先严格执行：可选标题确认、TTS、照稿字幕、独立真转写审核、提示词落盘、全部光栅配图。配图阶段由运行时代理调用 `qiushuiai-ip-qiushui`，默认启用编号交替人物模式：奇数图使用 qiushui 并带头像参考，偶数图使用一位漂亮、专业、认真工作的职场女性 / 女性知识工作者且默认不带 qiushui 头像参考；偶数图只有在文案确实需要多人关系时才加入 qiushui，此时 qiushui 必须使用头像参考身份并作为人物主角参与核心动作。`视频.md`、审核后的 `字幕.srt` 与 `字幕.words.json` 在渲染阶段保持只读。程序先把审核字幕单调对齐到字级真实时间；Director 继续使用原字幕编号和边界，烧录层另按社交横屏阅读节奏切成单行短字幕并保存为 `日志/字幕/渲染字幕时间轴.srt`。短字幕按完整意群切分；只要遇到 `，` `。` `？` `！` `、` 就必须断句，允许跨原 SRT 条目边界合并意群，但最终显示出来的每行字幕不得保留任何标点符号。起止时间直接取该条首末发音字符的真实时间，不得平均估时或修改文本。每张场景图生成后，由运行时代理直接发送 `scene/scene-*/画面.png` 给用户确认；脚本不再写 `review-state.json` 或维护二次确认状态。确认后每场使用同一组边界切割全片音频、制作白板动画并完成无字幕音画合成；全片拼接后，再统一烧录 `日志/字幕/渲染字幕时间轴.srt`。任何场景失败都终止全片。

白板提示词固定要求纯白背景、黑色手绘线条、少量强调色、教学图解布局，禁止摄影写实、渐变、阴影、水印和大段文字。语义审核允许抽象隐喻和简化图标，但不允许用无关的泛化意象替代该场必须表达的主语、对比两端、角色分工、关键判断或收束结论。

Python 内核将画面转为自适应阈值线稿，以网格块最近邻顺序逐步显现，并在当前绘制位置叠加手部素材。场景旁白长于绘制动画时，使用末帧克隆延长画面；若 `CONFIG.md` 提供 `background_image`，则在场景最终合成时直接把接近纯白的视频背景替换为该图，并与该场音频一次导出无字幕 `场景成品.mp4`，不再额外生成 `白板动画-背景版.mp4`。全片拼接完成后，再统一烧录最终字幕。

配图出图时不得用上一场图片作为通用 `--ref`，避免把奇偶人物身份串错。只有需要 qiushui 参考身份的图片才带 qiushui 头像 `--ref`：奇数图必须带；偶数职场女性单人图不得带；偶数多人图若包含 qiushui 则必须带，并在提示词中声明参考图只用于 qiushui。配置 SAM3 时，视觉模型识别主要对象并逐对象请求蒙版；绘制内核合并重叠蒙版、逐对象恢复彩色原图，最后绘制背景。未配置 SAM3 时自动走原版单通道模式。

TTS 只对完整 `视频.md` 执行一次。场景音频从根目录 `配音.mp3` 按渲染时间轴边界精确切出；`日志/字幕/渲染字幕时间轴.srt` 作为整片最终烧录输入保留，不再逐场烧录字幕。绘制动画默认保持固定基础笔速；仅当原始绘制时长超过场景语音时长的 95% 时，才压缩到 95% 以内，剩余时间克隆完成画面末帧。若绘制提前完成，不拉长绘制过程。若启用背景替换，只替换视频底层，不得改写字幕、配音或时间轴。禁止逐场重新 TTS/ASR，禁止使用 `-shortest` 截断最终场景成品。

所有场景统一为 1920x1080、25fps、H.264/AAC，保证 concat demuxer 可以无重编码拼接。全片 `成品-有字幕.mp4` 完成后，脚本先写出 `封面/cover-16x9.md`、`封面/cover-9x16.md`、`封面/cover-request.json`、`封面/封面文案.json` 与 `封面/封面生成说明.md`。随后由运行时代理**直接调用** `qiushuiai-video-cover` 生成封面：参数语义固定为 `platform=generic`、`aspect=both`、`form=subject-led`，`text-level` 按 `标题.md` 是否有 `line2` 取 `title-subtitle` 或 `title-only`；优先读取作品目录内的 `00-约定/封面生成约定.md`，若存在 `00-约定/头像.png`，只把它作为身份参考图传给封面 skill，不把 `scene/scene-01/画面.png` 或其他场景图作为参考图。这里明确**不使用** `textcard` 分支。横版交付图为 `16:9`，核心内容收在居中的 `4:3` 内容区；竖版交付图为 `9:16`，核心内容收在居中的 `3:4` 内容区。待 `封面-横版-16x9.png` 与 `封面-竖版-9x16.png` 落盘后，再运行 `--phase finalize`，按成片真实宽高自动选封面，将匹配比例的封面缩放到与视频同尺寸，替换视频第 1 帧，输出 `成品-有字幕-带封面.mp4`。

## 断点续跑

`标题.md`、音频、审核字幕和提示词未变化的画布可按文件存在性复用，但 `标题.md` 只有在本轮用户已确认时才可跳过标题关卡。`--phase audio` 只生成并审核音频字幕；默认 `--phase images` 生成全部画布并停住，由运行时代理发图给用户确认；确认后直接使用 `--phase render`。渲染阶段始终从只读根音频和渲染时间轴重新切出场景音频、平移场景字幕并重建场景视频，防止旧时间轴产物被误复用；`--force` 还会重做图片，同时允许重做封面与首帧封面版。

如果文稿改变了场景数量或顺序，使用 `--force`，避免旧场景目录被误用。

## 验收标准

1. 两个及以上场景的测试文稿能够输出一个可播放的 `成品-有字幕.mp4` 与 `成品-有字幕-带封面.mp4`。
2. `ffprobe` 显示视频同时包含 H.264 视频流和 AAC 音频流。
3. 每个场景都出现手部跟随的渐进绘制过程，而不是静态幻灯片。
4. 旁白结束前画面不会提前消失；绘制较短时保持完成画面。
5. 字幕与各自场景音频同步，场景拼接后顺序正确。
6. `封面-横版-16x9.png`、`封面-竖版-9x16.png` 与 `成品-有字幕-带封面.mp4` 存在，且首帧与所选封面一致。
7. 删除原 storyboard-ai 目录后，本 skill 仍可独立运行。
