# Qiushui 职场风正文配图

## 核心定位

为中文文章设计 16:9 横版正文配图，**并把每张图落盘成可直接出图的提示词**。目标不是做商业插画、PPT 信息图或可爱卡通，而是把文章里的关键判断、流程、结构、状态或隐喻，构思成一张清爽、有创意、可读但不说明书的手绘解释图。

本技能有两种产物模式：

- **规划/提示词模式**：先产出 `配图/配图策划.md`、`配图/*-配图提示词.md`、`配图/*-对应文案片段.md`，不生成 PNG。
- **实际出图模式**：当用户明确要求“生成图片/做图/输出 PNG”，或被视频流水线调用且需要根目录 `NN-主题-配图.png` 时，若当前运行时是 ChatGPT / Codex 且暴露了原生 `image_gen` / `imagegen` 工具，**必须直接调用原生工具逐张生成**。不要因为项目存在 `qiushuiai-image-gen` 配置、Seedream 默认 provider、API key 或脚本入口，就改走 `qiushuiai-image-gen/scripts/main.ts`。只有当前运行时没有原生光栅图像工具、原生工具明确不能接收本次必需参考图、原生工具无法返回可落盘图片，或用户明确指定外部 provider/model 时，才允许回落到 `qiushuiai-image-gen/scripts/main.ts`，由其 CONFIG / env / CLI 参数决定 provider 和 model。

默认视觉 IP 是“qiushui / 秋水”：一个小号、冷静、认真、略带荒诞感的知识工作者角色，优先保留参考头像中的人脸身份（发型、眼镜、脸部识别度、整体气质），再把身体适配成手绘正文配图里的小角色。若没有参考头像，则回退到内置的秋水角色描述。qiushui 必须参与画面的核心动作，但在配图里是“参与的配角”而不是抢镜的主角。默认每张图都必须有 qiushui；是否加入其他人物，要根据该张图对应的文案片段和场景语义来决定。

白板视频配图或用户明确要求“奇数用参考图、偶数用美女”时，启用**编号交替人物模式**：奇数图使用 qiushui 作为人物主角并使用头像参考；偶数图使用一位漂亮、专业、认真工作的职场女性 / 女性知识工作者作为人物主角，默认不出现 qiushui。偶数图女性头像使用诺贝尔奖得主官方肖像插画感：白底逻辑、黑色有力线稿、暖金 / 赭金色块阴影、清晰理性的五官结构、克制的学者气质；但这种肖像感只用于脸部和头部气质，整张图仍然是纯白手绘正文配图。若偶数图对应文案确实需要多人关系，可以加入 qiushui，并使用头像参考身份；只要 qiushui 出现，他也必须作为画面中的人物主角参与核心动作，不能被画成路人、背景人或弱配角。无论哪种模式，画面的第一主角仍然是概念结构、物件和信息流，人物都要服务这张图的核心表达。

## 头像参考规则

- 如果用户明确传了头像路径、截图或参考图，优先使用用户提供的头像作为同一人物身份来源。
- 如果用户没传头像，读取 `CONFIG.md`：
  - 若 `default_avatar_ref` 已配置且 `use_default_avatar_when_missing: true`，则按默认头像走参考身份模式。
  - 若没有可用头像，则退回纯文字版 qiushui 角色描述。
- 只要用了参考头像，提示词里必须明确：
  - 使用参考图中的同一个人，不要重设计成相似新人物。
  - 保留脸部身份、发型、眼镜、肤色和整体可辨识度。
  - 身体、服装、动作可以按正文配图风格适配。
- 在编号交替人物模式中：
  - 奇数图必须使用参考头像作为 qiushui 身份来源。
  - 偶数单人职场女性图不得使用 qiushui 头像参考，避免把女性人物画成 qiushui。
  - 偶数多人图若包含 qiushui，出图时要带头像参考，并在提示词里明确参考图只用于 qiushui，不用于职场女性主角。
- 本技能在规划/提示词模式下只产 prompt 文件，不直接执行头像参考；交付时必须把“出图时要带上参考头像”说明清楚。
- 本技能在实际出图模式下必须执行头像参考规则：奇数图和需要 qiushui 身份的图片，调用原生 `image_gen` 时传入参考头像；回落到 `qiushuiai-image-gen` 时使用 `--ref <头像路径>`。偶数职场女性单人图不得传 qiushui 头像参考。

## 工作流

### 1. 消化正文

先读用户给的正文、链接、Notion 页面、Markdown 文件或截图内容。提炼：

- 核心观点是什么
- 哪些段落承担认知转折
- 哪些内容适合用图解释
- 哪些地方只适合文字，不需要图

不要平均配图。优先选择“认知锚点”，例如：核心判断、两个断点、输入输出闭环、分流、前后对比、一鱼多吃、承接路径、常见坑、角色状态变化。

### 2. 先出配图策略

如果用户只是说“分析怎么配图 / 思考哪些地方需要配图”，先给 shot list。每张图写清楚：

- 放在哪个段落后
- 图的主题
- 画面标题
- 核心意思
- 结构类型
- qiushui 在图里做什么
- 人物模式：默认 qiushui 模式，或白板编号交替人物模式中的奇数 qiushui / 偶数职场女性 / 偶数职场女性 + qiushui
- 是否需要其他人物；若需要，写清是单人 / 双人 / 多人场景，以及人物之间的关系
- 建议元素
- 建议中文标注词

默认 4-8 张。文章很短时 1-3 张；长文也不要轻易超过 9 张。够用就好，避免把正文做成画册。

### 2.5 落盘对应文案片段

一旦决定最终要出几张图，就要把原文按**当前 skill 已经确定的拆图结果**同步拆成同样数量的文案片段文件。这里**不改变拆图逻辑**，只是把“这张图对应原文哪一段 / 哪几段”落盘成独立文件。

- 命名：`配图/NN-主题-对应文案片段.md`
- 数量：必须和最终图片数量完全一致
- 编号与主题：必须和 `配图/NN-主题-配图提示词.md`、根目录 `NN-主题-配图.png` 一一对应
- 内容：只放这张图对应的原文段落或相邻几段原文，不要加入新的改写、总结、解释、点评或元信息
- 允许：为了让片段自洽，可以保留必要的相邻上下文段落
- 不允许：为了凑数量而机械均分全文；仍然要以认知锚点和当前拆图结果为准

如果这些文案片段后续会被视频流水线用于匹配字幕时间轴，片段边界还必须遵守以下规则：

- 片段开头优先选择“完整表达句”或“例子正式展开句”，不要从容易被 ASR/SRT 切碎的位置开始。
- 尽量避开只承担转场的短句、问句、序号句和总领句，例如“具体来说”、“第一”、“第二”、“第三”、“那两者能不能一起用？”、“这里有两个常见误区。”。
- 如果一张图的主题需要覆盖上述转场句或序号句，可以把这些内容体现在 `配图策划.md` 或提示词主题里；`对应文案片段.md` 则从后面更稳定、可连续匹配的正文句开始。
- 中英文术语混排的句子如果容易在字幕里被拆开，例如 `Skill`、`Sub Agent`、`Agent` 附近，片段开头不要卡在这些术语前后；优先从下一个完整中文句或例子句开始。
- 片段结尾也尽量落在完整句末，不要为了包含下一张图的铺垫句而把结尾卡在半句、转场句或序号句上。

如果最终拆成 5 张图，就要同步落 5 个文案片段文件，例如：

```text
配图/01-主题-对应文案片段.md
配图/02-主题-对应文案片段.md
配图/03-主题-对应文案片段.md
配图/04-主题-对应文案片段.md
配图/05-主题-对应文案片段.md
```

这些文件用于建立“图片编号 ↔ 原文片段”的强关联，比“建议放在哪个段落后”更明确。

### 2.6 提炼画面标题

每张图都必须有一个会写进画面里的中文短标题。这个标题的用途不是给图片起名，也不是描述构图隐喻，而是表达这张图对应文案片段里的内容，作用类似文章每一节的小标题：观众看图前先知道这一段正在讲什么。

- 来源：必须基于同编号 `配图/NN-主题-对应文案片段.md` 提炼。
- 写法：优先回答“这一段在讲什么？”，而不是“这张图像什么？”。
- 长度：不超过 12 个中文字符。
- 忠实：不得为了好看、押韵、制造悬念或适配画面物件而偏离文案意思。
- 区分：可以不逐字复用原文小标题；如果原文没有小标题，就从对应文案片段中提炼准确小标题。
- 禁止：不要写结构类型名、视觉隐喻名、文件名式长标题或纯抽象标签。

推荐：

- `CLI 适合本地任务`
- `MCP 适合连接外部系统`
- `Skill 适合沉淀固定流程`
- `不要为简单任务付说明书成本`
- `先判断任务在哪一层`

不推荐：

- `本地任务`
- `连接系统`
- `沉淀方法`
- `奇怪的工具箱`
- `Workflow`
- `系统架构图`
- `第一部分：CLI`

### 2.7 判断是否需要额外人物

在每张图已经对应到明确文案片段之后，再判断画面是单人还是多人：

- 默认优先单人：如果这一张主要表达流程、结构、系统、状态、隐喻、前后对比，且不依赖人与人关系，默认只保留 qiushui 一人。
- 允许多人：如果对应文案片段明显在讲交流、陪伴、协作、社群、用户、客户、信任、现场互动、围观、承接关系、分发给人、线下连接等关系语义，可以加入 1 个或多个美女配角。
- 多人不是装饰：新增人物必须服务该张图的核心意思，不能为了“更热闹”硬加人。
- 主次不能反转：即使加了美女配角，qiushui 仍然是固定 IP 锚点；概念结构仍然是第一主角；新增人物只是场景配角。

### 2.8 白板编号交替人物模式

当本技能被 `qiushuiai-video-pipeline-whiteboard` 调用，或用户明确要求“奇数用参考图、偶数用美女”时，不走上面的默认人物判断，改用本节规则：

- 奇数编号图：人物主角是 qiushui，使用用户提供头像或 `CONFIG.md` 默认头像作为参考身份。提示词必须保留同一人物身份，并要求 qiushui 参与核心动作。
- 偶数编号图：人物主角是一位漂亮、专业、认真工作的职场女性 / 女性知识工作者。她应像正在办公室、白板、项目现场或内容工作流中解决问题的人，不是网红、模特、二次元美少女或海报人物。默认不出现 qiushui。
- 偶数编号图如果对应文案确实需要多人关系，可以加入 qiushui；此时出图必须带 qiushui 头像参考，并在提示词中明确参考图只用于 qiushui，不用于职场女性。只要 qiushui 出现，他也必须作为画面中的人物主角参与核心动作，不能被画成路人、背景人或弱配角。
- 无论奇偶，概念结构、物件和信息流仍然是画面的第一主角；人物要画小、靠边、参与动作，不能把配图做成人物海报或合影。
- `配图/配图策划.md` 每张图必须写明人物模式，例如：`奇数｜qiushui｜使用头像参考`、`偶数｜职场女性｜不使用 qiushui 头像参考`、`偶数｜职场女性 + qiushui｜qiushui 使用头像参考`。

### 3. 落盘策划与提示词

在逐张提示词落盘前，先把整组配图策略写成总控文件：

- 命名：`配图/配图策划.md`
- 内容：每张图的编号、主题、画面标题、核心意思、结构类型、建议放置位置、人物模式、人物动作、是否需要其他人物
- 作用：承载 shot list / 主题说明 / 结构类型 / 放置建议，避免把这些元信息污染到单张提示词文件

对每张选定的图，按 `references/prompt-template.md` 把模板填成完整提示词，写入一个**纯提示词文件**：

- 命名：`配图/NN-主题-配图提示词.md`（在 workspace / 作品目录内）或用户指定路径；`NN` 两位序号。
- **文件内容必须是纯提示词正文**：不加 YAML frontmatter、不加 `#` 标题、不加任何中文说明 / 注释 / 元信息。出图用 `--promptfiles` 会把文件**原样**喂给模型，混入杂物会污染出图。shot list、主题说明、结构类型这些放别处（如 `配图/配图策划.md`），**绝不塞进提示词文件**。
- 每张独立成图、各发明一个新隐喻，不复用过往构图。

### 3.5 生图后端选择

如果用户只要求规划、分析、shot list、提示词，停在提示词文件交付，不生成图片。

如果用户明确要求“生成 / 输出 / 做图 / 帮我生成”，或本技能被 `qiushuiai-video-pipeline-whiteboard` 调用且当前阶段需要实际 PNG，则按以下顺序生成：

1. **ChatGPT / Codex 原生工具是硬优先级**：只要当前运行时暴露了原生光栅图像工具，例如 `image_gen` / `imagegen`，就必须直接调用该工具逐张生成。每张图单独调用，不能把多张图拼在一张里。需要 qiushui 参考身份的奇数图，把 `CONFIG.md` 默认头像或用户头像作为参考图传入；偶数职场女性单人图不得传 qiushui 头像参考。生成后保存或转存到作品根目录 `NN-主题-配图.png`，供视频流水线继续消费。
2. **不要把本地脚本当成 Codex/ChatGPT 内的默认出图路径**：项目里存在 `.qiushuiai-skills/qiushuiai-image-gen/CONFIG.md`、`default_provider: seedream`、API key、或 `qiushuiai-image-gen/scripts/main.ts`，都不是回落理由。当前运行时有原生工具时，禁止主动调用 `qiushuiai-image-gen`、Seedream、OpenRouter、DashScope、codex-cli 等外部脚本/接口。
3. **只有满足明确回落条件才用 `qiushuiai-image-gen`**：当前运行时没有原生图像工具；原生工具明确不能接收本次必需的本地参考图；原生工具生成后无法返回或保存可用于流水线的图片；用户当前明确指定某个外部 provider/model。满足这些条件之一时，才回落到 `qiushuiai-image-gen/scripts/main.ts`。
4. 回落到 `qiushuiai-image-gen` 时，**不得在本技能里写死 provider/model**。模型选择交给 `qiushuiai-image-gen` 的 CLI 参数、项目 CONFIG、环境变量和用户 CONFIG。若指定 provider 不支持参考图或失败，应停止说明，不要静默换模型。

生成每张图时必须同步记录一条图片生成追踪信息，写入作品 `日志/视频制作日志.md`。记录时间是硬要求，不是可选复盘项：**每次调用出图工具前先记 `start_at`，工具返回后立即记 `end_at`，并计算 `duration_seconds`**；失败重试也要保留失败记录或在同一行写清 `retry_count` 与失败原因。不要等用户追问后再从文件 mtime 倒推。

图片生成追踪表至少包含这些字段：

```markdown
| 编号 | 目标文件 | 后端 | 工具/模型 | 使用参考图 | 参考图路径 | start_at | end_at | duration_seconds | retry_count | 失败原因 | 生成源路径 | 复制到作品目录时间 |
|---|---|---|---|---|---|---|---:|---:|---:|---|---|---|
```

- 时间格式：使用本地时区 ISO 或 `YYYY-MM-DD HH:mm:ss`，同一作品内保持一致。
- `duration_seconds`：按 `end_at - start_at` 计算；不能只写“大约几分钟”。
- 使用原生 `image_gen` / `imagegen` 时，也必须由运行时代理手工记录开始、结束和耗时。
- 使用参考图填 `是`，并写绝对路径；未使用填 `否`，参考图路径填 `无`。
- 编号交替人物模式下，奇数图默认应记录使用 qiushui 头像参考；偶数职场女性单人图必须记录未使用 qiushui 头像参考。

回落命令示例：

```bash
# 没有头像参考时：
npx -y bun ${IMAGE_GEN_SKILL_DIR}/scripts/main.ts \
  --promptfiles 配图/NN-主题-配图提示词.md --image NN-主题-配图.png --ar 16:9

# 有头像参考时：
npx -y bun ${IMAGE_GEN_SKILL_DIR}/scripts/main.ts \
  --promptfiles 配图/NN-主题-配图提示词.md --ref /abs/path/to/avatar.png \
  --image NN-主题-配图.png --ar 16:9
```

> 是否用 Seedream、OpenAI、OpenRouter、Google、Codex CLI 等模型，属于出图方选择；默认 provider/model 由 `qiushuiai-image-gen` 的 CONFIG（如 `default_provider` / `default_model`）和环境变量决定。

每张图只讲一个核心结构。提示词必须包含：

- 16:9 横版中文正文配图
- 纯白背景
- 黑色手绘线稿
- 少量红色/橙色/蓝色中文手写批注
- 一个基于对应文案片段提炼的中文画面标题，像文章小标题 / 白板页眉一样帮助观众理解这一段
- 大量留白
- 默认模式下，qiushui 作为参与核心动作的配角（画小、放一侧，见下方「弱化原则」）
- 编号交替人物模式下，奇数图用 qiushui，偶数图用诺贝尔奖得主官方肖像插画感的职场女性；偶数多人图中 qiushui 出现时也必须作为人物主角参与核心动作
- 默认模式下如文案片段需要，可加入 1 个或多个美女配角；编号交替人物模式下偶数图默认使用职场女性主角
- 如果有参考头像：明确保留同一人物身份
- 禁止 PPT、商业插画、幼稚可爱、复杂架构、泛化类型标题、视觉隐喻标题

#### 弱化原则（重要）

人物是配图的参与者，不是封面主角。每张图都要：

- 把人物画小，身高大约只占画面高度的 1/5～1/4，放在画面一侧，不要占据正中央。
- 第一眼被看到的必须是表达概念的结构、物件和信息流（它们画得最大、最醒目），人物只是小小地参与其中一个动作。
- 角色身上的暖色点缀要克制；表达流程/路径/箭头的橙色用另一种更深更纯的橙，避免人物和功能色糊在一起。

不要复刻过往案例。案例只提供风格密度和 qiushui 的参与方式，不能直接复用已有构图，除非用户明确要求复刻某张图。每次都要从当前文章重新发明一个奇怪但成立的隐喻。

### 4. 自检（提示词层面）

落盘前对每条提示词自检：是否只讲一个核心结构、是否包含上面「提示词必须包含」的要点、画面标题是否忠实概括对应文案片段而不是描述构图隐喻、人物是否被弱化为参与者而不是画面封面主角、如果有参考头像是否写明保身份约束、编号交替人物模式下奇偶人物是否正确、偶数单人图是否避免 qiushui 头像参考、有没有混入非提示词内容。

`references/qa-checklist.md` 里那份是**图像级**检查（人物太大太抢镜、只装饰不参与、画面太满、像 PPT、中文错字、缺少画面标题、标题变成泛化类型名或视觉标签、画风太可爱、背景不干净白底等）——本技能不出图，故这份清单作为**交付给出图环节**的参考：出图方生成后对照它判断是否重生成 / 局部编辑（重生成 = 按反馈改提示词文件后重跑 image-gen）。

### 5. 交付

本技能至少产出提示词文件；实际出图模式下还必须产出 PNG。落盘到 workspace / 作品目录内，按顺序命名：

```text
配图/配图策划.md
配图/01-topic-name-配图提示词.md
配图/02-topic-name-配图提示词.md
配图/01-topic-name-对应文案片段.md
配图/02-topic-name-对应文案片段.md
01-topic-name-配图.png
02-topic-name-配图.png
```

不要覆盖已有提示词文件或 PNG，除非用户明确要求替换。图片保存到作品根目录为 `NN-主题-配图.png`。如果本次使用了头像参考，交付时要一并给出参考图路径或说明“使用 CONFIG.md 中默认头像”。

交付时必须保证：

- `配图/` 下 `*-配图提示词.md` 数量 = `配图/` 下 `*-对应文案片段.md` 数量
- 提示词、文案片段、根目录配图三者的编号与主题完全一致
- 每张图都能明确对应回一份原文片段文件

## 输出口径

策略输出短而准。交付要包含：

- 落盘了几条提示词
- 落盘了几条对应文案片段
- 每条图的用途（主题 / 画面标题 / 结构类型）
- 提示词文件路径（`配图/NN-主题-配图提示词.md`）
- 对应文案片段路径（`配图/NN-主题-对应文案片段.md`）
- 哪些图最稳，哪些是可选
- 本次是否使用了用户头像或 `CONFIG.md` 默认头像；若启用编号交替人物模式，逐张说明哪些图需要 `--ref`
- 生图后端：说明本次是否使用运行时原生 `image_gen`；若回落到 `qiushuiai-image-gen`，说明使用的 provider/model 或配置来源
- 图片生成追踪：列出每张图的后端、是否使用参考图、开始时间、结束时间、耗时、重试情况和最终文件路径
- 下一步出图提示：如果本次只落盘提示词，则提示可用运行时原生 `image_gen` 或 `qiushuiai-image-gen --promptfiles` 出图到作品根目录；只有需要 qiushui 参考身份的图片才带参考图 / `--ref`

不要长篇解释风格理论；让图自己说话。
