# QA Checklist

## 必过项

- 是 16:9 横版。
- 背景是干净白底。
- 有 qiushui。
- qiushui 承担核心动作，不只是装饰。
- qiushui 画小、放一侧（约占画面高度 1/5～1/4），是参与配角；第一眼先看到的是结构信息，不是 qiushui。
- 如果加入了其他人物，她们和文案语义强相关，不是为了热闹硬加。
- 如果加入了其他人物，她们仍然是次要配角，没有比 qiushui 更大、更亮、更居中。
- 如果使用了参考头像，人物脸部身份和参考图保持同一人，而不是重新设计的相似角色。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面有创意、有意思。
- 简洁清爽，结构主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读，每个标注只出现一次。
- 有且只有一个中文画面标题。
- 画面标题忠实概括对应文案片段的内容，像文章小标题，而不是描述构图隐喻或结构类型。
- 画面标题清楚、可读，但不抢主结构，不像 PPT 大标题、课程标题或封面标题。
- 人物暖色点缀克制；流程/箭头用更深更纯的橙，不和人物撞色。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 缺少画面标题，或同一张图出现多个标题。
- 出现“常见坑 / Workflow / 系统架构图 / 路线图”等泛化类型标题。
- 标题只是“本地任务 / 连接系统 / 沉淀方法”这类空泛标签，不能表达对应文案片段的具体内容。
- 标题太大、太像 PPT 页标题、课程标题或封面标题。
- 标题和短标注混成大段解释。
- qiushui 像吉祥物、表情包或可爱卡通。
- qiushui 太大、太居中、太抢镜，盖过了结构信息。
- 新增美女人物比 qiushui 更抢镜，或者整张图看起来像人物海报。
- 额外人物和文案没关系，只是装饰性站位。
- 使用了参考头像但人物脸明显变成了另一张脸。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让 qiushui 成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：强调 deadpan、blank serious expression、not cute、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 标题不准：回看对应文案片段，改成表达“这一段在讲什么”的小标题；不要按画面物件或结构类型命名。
- 太像旧案例：保留核心意思，换掉主物件和 qiushui 动作。
- 脸跑偏：加强 same identity、do not redesign、keep hairstyle/glasses/face identity 的提示。
- 配角抢镜：减少配角数量，缩小配角尺寸，移到边缘，改成半身/背影/围观姿态，或直接回退单人图。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
